# One book experience, two generated artifacts

Status: shipped on 2026-10-10. This document describes the current product and its remaining evaluation boundaries. Earlier proposals are retained in Git history, not as current capability claims.

## Two outputs from one intake

The **editorial digest** is original, paragraph-led prose for a person reading the book page. The **agent skill** is structured knowledge engineering: chapter methods, frameworks, practical rules, glossary, patterns, cheatsheet and source references. Neither substitutes for the other.

The public shelf retains its historical editorial workflow in `scripts/generate-book-wave.mjs`, `docs/EDITORIAL_STYLE.md` and `content-engine/CONTENT_GENERATION_SPEC.md`. It generally targets a roughly 1,500-word argument with four to six idea-led sections; historical pages may also have been edited or generated by other runs.

Private managed conversion and CLI 0.7.0 or later share `_shared/book-reader.mjs` and `book-reader-prompt.json`. They write `reader/digest.md`, metadata and a paragraph evidence map separately from `book.md` and `skill/`. The reference-style `book.md` remains available in packages; it is not the finished reader summary. Accepted skill artifacts survive an editorial retry.

The active reader uses bounded original excerpts from extracted sections, source-dependent length limits and paragraph-specific cited-source review. It records the prompt version, instruction hash and review provenance. This model-assisted review is fallible. A customer's uploaded review flags are not independent server verification.

See the [prompt inventory](../content-engine/prompts/book-digest/README.md) and [executable reader contract](../content-engine/prompts/book-digest/reader-digest-v2.md). The proposed model-generated source brief and broader editorial review remain unwired design references.

## Shared reading experience

Public and private readers reuse the overview, purchase and agent-prompt components. The private page presents:

1. Copy prompt for your AI.
2. When to reach for this book and what the book is about.
3. The editorial summary with idea-led sections.
4. Optional expandable core lessons and frameworks.
5. Read the full book, with an Amazon title-and-author search for uploaded books rather than an invented edition link.
6. Put this book to work, with the Agent Skill Card collapsed inside it.

Completed readers no longer show separate Use with AI, download, source-processing or Add/Replace source controls. CLI exports, offline installation and managed source revisions remain optional capabilities. Unfinished jobs retain processing and spending controls.

Older private conversions without `reader/digest.md` show an honest missing-summary state. Updating the CLI does not backfill those books. The full Smith source and its duplicate, plus the separate Chapters 1–3 excerpt, received source-grounded editorial digests during this release. Their sources, skills, covers and billing were preserved; no new paid generation was used for that repair.

The Smith cards represent two source scopes: a full book and a Chapters 1–3 excerpt. Exact-text duplicates are grouped by source hash. The cover typography is decorative; repeated words copied from a card do not mean the same source was processed twice.

## Managed and own-agent routes

| Route | Generation | Where the result is used |
| --- | --- | --- |
| Managed, recommended default | Upload source; approve the returned token rates and spending limit; hosted generation and review produce both outputs; optional cover runs separately | Private reader and hosted retrieval; optional offline export/install |
| Bring your own agent, Private library | Current agent answers the same generation and review requests; completion automatically imports the new AWB workspace into the selected account | Same private reader and hosted retrieval; no AWB hosted text-generation or cover charge for the transfer |
| Bring your own agent, Device only | Same local workspace flow; no AWB login or upload | Local digest and optional installed book skill; the user's model-provider terms still apply |

Library sync is a **one-time handoff of a newly completed AWB workspace**. A failed transfer can be retried without regenerating. Later local revisions stay local by product decision; they do not update the hosted copy. Importing arbitrary upstream/manual skill packages is outside scope.

Hosted sync does not publish a book to the public catalog. It uploads the extracted source and structured results, validates artifact structure and citation bounds, and indexes the private methods. It does not execute uploaded skill instructions or establish semantic truth.

## Retrieval and activation

One generic Answer with Books skill connects an agent to the private library. The authenticated `book-library` endpoint uses keyword/vector retrieval to return relevant methods, bounded source excerpts and citations. The user's current agent applies the evidence and writes the answer. The server does not execute a saved `SKILL.md`.

A per-book local installation is optional for offline use. Exporting a ZIP does not activate a skill in the agent. The package contains the reader/reference artifacts, skill and source references; installation is a separate, requested action. Logout revokes remote access but does not erase local files.

## Several sources, one guide

The agent and upload dialog offer **One guide** or **Separate books** when several sources are selected. Preserve an explicit choice. A combined intake keeps each source's identity, fingerprint, line coordinates, scope and disagreements, and uses one spending-limit review for managed generation.

Local `local add` preserves accepted notes/citations and guide identity, processes one new source and regenerates synthesis and the reader. Keep the AWB workspace and finish one revision before adding another. The new revision can update the same installed local skill.

Managed append/replace remains an agent/CLI revision operation with its own quote. It is absent from the completed reader UI. See the published [combined-guide documentation](https://docs.answerwithbooks.com/guide/combined-guides) for limits and commands.

## Managing the library

Manage Skills supports archive, restore and confirmed deletion of a book's complete revision history. Archived rows are paused, hidden from the active shelf and excluded from hosted retrieval; restoration rebuilds the index. Archiving does not remove local installations or cancel consumed charges.

Deletion uses ownership, active-worker and billing guards. It removes stored sources, generated artifacts, revisions and retrieval entries; required billing records remain. Database constraints prevent stale writes from restoring a deleted or archived job. These lifecycle actions require the signed-in web account, not an API key.

Books in the making uses the full-width processing queue. Completed readers focus on reading and applying the book.

## Verification and remaining boundaries

See [reader and management acceptance](verification/reader-management-2026-10-10/README.md) for production evidence and [workflow evaluation](BOOK_FLOW_EVALUATION.md) for the broader capability matrix.

The release passed 79 workflow checks, 46 CLI tests, worker-handler and real PostgreSQL/pgvector lifecycle checks. Signed-in production desktop/mobile checks covered reader structure, copy prompts, archive/restore/delete, hosted retrieval exclusion and the queue. Initial library sync and multi-source acceptance were established in the [0.6.0 release](verification/release-0.6.0-2026-10-10/README.md).

These results do not establish broad corpus quality, independent semantic-score parity, every external harness's fresh-session discovery, or a new paid full-book conversion. No such claims are made. The 0.7.1 documentation patch aligns the installed skill guidance and active setup links with the shipped behavior; historical release reports retain their original versions and evidence.
