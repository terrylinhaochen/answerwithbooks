---
title: "Generate with your own agent"
description: "Create a local summary and skill using the model access you already have."
---

Send this to your agent:

```text
Use Answer with Books to create a summary and reusable skill from my local file. Use my own agent for generation, then install the finished skill.
```

The agent extracts the source, answers generation and source-review requests, and saves progress locally. With device-only output, Answer with Books does not upload the source or make hosted generation calls. Your agent provider's data handling and charges still apply.

## What you need

- A command-capable agent and the current Answer with Books CLI.
- A local PDF, EPUB, DOCX, Markdown, HTML, RTF, or text source.
- Node 20 or later. First use may download an extraction runtime; scanned pages need OCR first.

Device-only work needs no Answer with Books account or repository clone. Syncing to your private library requires a connected account.

## What you receive

CLI 0.7.0 adds a separate paragraph-led editorial digest alongside `SKILL.md`, chapter notes, glossary, patterns, cheatsheet, and source references. Image generation and hosted library search are separate. Your package is saved locally. You can also choose to sync its first version to your private library. Keep the Answer with Books workspace if you want to add sources later. Uploading the original source through managed intake starts hosted processing; it does not transfer the work your agent already completed.

<Accordion title="How the agent drives generation">
With the current CLI, it prepares a work directory and repeats the next/respond cycle until the package is ready:

```text
local prepare ./book.pdf --output ./my-book
local next ./my-book
local respond ./my-book --input ./response.json --request REQUEST_ID
local install ./my-book
```

These are CLI arguments, not standalone shell commands. Use the [CLI prefix](/guide/cli). The agent writes responses to the current request, resolves source-review findings, and installs only a ready package. After the skill synthesis, it answers `book_reader` and `book_reader_review` requests using the same versioned editorial prompt as managed generation. These remain requests to your own agent, not hosted model calls. Selected private-library sync includes this reader digest.
</Accordion>

## Combine sources or update a guide

You can ask for one guide from several sources, then add material as your project develops. CLI 0.6.0 supports both workflows. See [Combine and update guides](/guide/combined-guides) for examples, version behavior, and current limits.

## Save to your private library

<Note>
Private-library sync requires CLI 0.6.0 or later and a connected Answer with Books account.
</Note>

Choose **Device only** or **Private library**. Device-only generation needs no AWB account. A private-library destination requires a connected account and permission to upload the extracted source and generated notes.

With CLI 0.6.0, `local prepare ./book.pdf --output ./my-book --destination library` selects automatic sync on completion. The agent retries a failed upload without regenerating the book. `local publish ./my-book` sends a completed AWB workspace later.

Once saved, the guide uses the same [private retrieval process](/guide/library) as managed books. Your current agent receives relevant methods and citations and writes the answer. AWB makes no hosted text-generation or cover-generation calls for this transfer; your agent provider's charges still apply.

Private-library sync is a one-time handoff. Later local revisions do not update the hosted copy. Updated local guides remain usable and installable on your device. No private upload automatically joins the public catalog.
